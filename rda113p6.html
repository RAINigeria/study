Option A — 2D Environment Scanner with Motion Detection
Option A · Advanced
2D LiDAR Scanner + Anomaly Detector
60 marks (Project) + 40 (Demo & Code)

Build a rotating distance scanner that maps a 2D slice of its environment using a Time-of-Flight (ToF) sensor mounted on a DC motor with encoder feedback. The system must continuously scan the room, track the angular position at each measurement, and detect changes in the environment — specifically, human presence indicated by a distance reading that was not there in the last 5 minutes — and alert when a change is detected.

VL53L0X / VL53L1X ToF Sensor DC Motor Hall Effect Encoder or Rotary Encoder Arduino / ESP32 Serial Monitor or LED Alert Motor Driver (L298N / L293D)
[ ToF Sensor ]─────→ [ MCU ]──encoder feedback──[ Motor + Encoder ] distance readings ↗ ↓ [ Scan Buffer ] (angle + distance) ↓ [ Comparison Engine ] (compare with 5-min map) ↓ [ Alert if Δdistance > threshold ] (LED / Serial / Buzzer)

Your scan loop must read the ToF sensor at known angular steps (driven by the motor and tracked by the encoder) and store a baseline map every 5 minutes. On each new scan, compare current readings to the baseline. If any angle shows a significant change in distance (e.g. ≥15 cm), trigger an alert. This indicates an object — likely a person — has entered the field.

  1. Motor control: Rotate the DC motor at a consistent, measurable speed. Use the encoder to read current angle in degrees (0–360°).
  2. ToF reading: At each encoder tick interval, read distance from the ToF sensor and store as (angle, distance) pairs.
  3. Baseline management: Store the first complete scan (or refresh every 5 minutes) as the reference environment map.
  4. Change detection: On every subsequent scan, compare each angle's distance to the stored baseline. Flag angles with significant deviation.
  5. Alert output: When a change is detected, output to Serial Monitor (with angle and delta distance) AND activate an LED or buzzer alert.
  6. Continuous operation: The system must run indefinitely without manual reset.

Option B — MQTT Height Reporter with Live Web Dashboard
Option B · Intermediate–Advanced
Doorway Height Sensor → MQTT → Web Dashboard
60 marks (Project) + 40 (Demo & Code)

Build a system that measures the height of a person passing under a doorway using a downward-facing ToF or ultrasonic sensor, publishes each height reading to an MQTT broker, and displays the latest received height on a webpage running on your laptop. The sensor must only trigger a new reading when a person is actively present under the doorway — not continuously.

VL53L0X / HC-SR04 Ultrasonic ESP8266 / ESP32 MQTT (Mosquitto / HiveMQ) HTML/JS Web Page (MQTT.js) Mounting bracket / doorframe setup
[ Sensor (facing down) ] ↓ detects presence [ ESP32 / ESP8266 ] - measure ceiling-to-person distance - compute height = door_height - sensor_reading - publish to MQTT topic: rain/doorway/height ↓ (WiFi) [ MQTT Broker ] ← (HiveMQ cloud or local Mosquitto) ↓ [ Laptop Browser - HTML page with MQTT.js ] - subscribe to rain/doorway/height - update display with each new reading - only updates when a new person arrives
  1. Presence detection: Only publish a height when a person is detected (distance reading below a threshold, indicating something under the doorway). Do not publish repeatedly when no one is present.
  2. Height calculation: The sensor reads distance from ceiling to object. Height = known door height − sensor reading. Calibrate this accurately.
  3. MQTT publish: Connect the ESP to WiFi, connect to MQTT broker, publish computed height to a defined topic each time a person passes.
  4. Web subscriber: Create an HTML file (opened in your laptop browser) that subscribes to the MQTT topic using MQTT.js (WebSocket). Display the last received height prominently. The display must not update unless a new message arrives.
  5. Demonstration: Show a person walking under the sensor — height appears on screen. Show that no update happens when no one is present.

Option C — LDR-Based Hallway Entry/Exit Detector
Option C · Intermediate
Smart LDR Array — Hallway Occupancy Tracker
60 marks (Project) + 40 (Demo & Code)

Using a pool of LDRs (Light-Dependent Resistors) positioned across a hallway entrance, build a system that detects whether a person is entering or leaving the hallway by analysing the sequence in which the LDRs are triggered. Log each event (ENTRY or EXIT) with a timestamp to the Serial Monitor, and optionally display a live count on an LCD or via LEDs.

LDRs (at least 2, ideally 3–4) Resistors (voltage divider) Arduino / ESP32 Optional: I2C LCD Display Optional: LEDs for visual feedback Serial Monitor (mandatory output)
Hallway entrance (top view): OUTSIDE [ LDR-1 ] [ LDR-2 ] INSIDE ─────────────────────○──────────○────────────────────── ↓ ↓ Person triggers LDR-1 first → then LDR-2 = ENTRY Person triggers LDR-2 first → then LDR-1 = EXIT [ Arduino / ESP ] - reads analog values of each LDR - detects trigger sequence - logs "ENTRY" or "EXIT" to Serial Monitor - updates running count of people inside
  1. Hardware setup: Mount at least 2 LDRs in a line across the hallway entrance (inner and outer positions). Wire each as a voltage divider to an analog pin.
  2. Calibration: Read ambient light levels and set appropriate shadow-detection thresholds for your lab lighting.
  3. Sequence detection: Track which LDR is blocked first. If LDR-outer triggers before LDR-inner → ENTRY. If LDR-inner triggers first → EXIT. Allow a configurable time window (e.g. 2 seconds) for the sequence to complete.
  4. Event logging: Print each ENTRY or EXIT event to Serial Monitor with a timestamp (millis() or RTC if available) and current person count.
  5. Visual feedback (bonus): Display current inside count on an LCD or with a row of LEDs.
  6. Edge case handling: If only one LDR is triggered (person stops mid-way), ignore the event.
